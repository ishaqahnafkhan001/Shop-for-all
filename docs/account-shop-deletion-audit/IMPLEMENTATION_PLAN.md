# File-level implementation plan and rollout gates

This is a proposed change map. **No listed application change, schema, index, endpoint, migration or UI component was created by this audit.** Existing files are linked; future filenames are explicitly marked proposed. Resolve the policy gates first, then implement small vertical changes using the existing Express/Mongo/worker architecture.

## Stage 0 — ownership, inventory and retention contract

Approve SECURITY.md, RETENTION.md and OPEN_QUESTIONS.md. Perform an authorized read-only operational census: actual collections/indexes, legacy identity consistency, owner binding, other memberships, active orders/returns/payments/POs/reservations, provider environments/assets and backups/log copies. Produce resource-specific approved selectors and hold rules from DATA_INVENTORY.md. No destructive endpoint may be enabled at this stage.

**Acceptance gate:** every resource is owned/shared/unresolved, every destructive category has an approved policy, and unresolved active obligations or ownership conflicts have explicit blocking behavior. No legal periods or account cascade rules are inferred from code. Rollback: documentation/config review only.
