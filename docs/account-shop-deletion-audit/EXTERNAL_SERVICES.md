# External-resource deletion feasibility

Repository facts are separated from provider capabilities. Official provider documentation was checked on 20 October 2026 where cited. No API credentials, provider account settings, resources or live data were read or changed.

Capability labels: **Existing primitive** = callable code exists, but tenant deletion is not implemented. **Provider supported, not integrated** = official documentation establishes a capability, but this app has no complete deletion workflow. **Requires verification** = API, contract, account settings or ownership evidence unavailable. **Outside full control** = copies/obligations the application cannot guarantee to erase.

## Required media manifest

Before removing database references, persist bounded entries for: trusted Cloudinary product environment, asset/public ID, resource type (`image`/`video`/`raw`), delivery type (`upload`/`private`/`authenticated`), original URL where still needed for reconciliation, owner evidence, all current/historical/retained/shared references, action/hold, attempt and verified result. The current uploader usually preserves public IDs, not immutable Cloudinary `asset_id`; public IDs alone do not prove exclusive tenant ownership. Unknown entries block full completion or remain explicitly disclosed exceptions.

Do not derive an ID by stripping a URL extension and blindly call destroy. Transformations, versions, delivery types, URL escaping, raw file extensions, external clouds and renamed assets make that unreliable. Do not call prefix/folder deletion against `shop_products` or `support_attachments`. A current tenant-specific folder helps discovery but does not replace exact ownership verification.

Use the existing server SDK for exact known resources with checked success/already-absent outcomes and invalidation. Provider documentation supports individual destroy and resource-type-aware deletion; a video requires the corresponding video type. This is a provider capability, not an existing tenant eraser. [Cloudinary asset deletion](https://cloudinary.com/documentation/delete_assets).

Origin deletion is distinct from CDN and backup deletion. Request invalidation; account-specific signed URL/custom CDN behavior must be verified, and visitors' browser/proxy/search copies cannot be universally purged. [Cloudinary CDN invalidation](https://cloudinary.com/documentation/invalidate_cached_media_assets_on_the_cdn).

Cloudinary documents backup/version removal capabilities separately, including Admin API backup-version deletion. Whether backups are enabled, required permissions, account limits, external backup buckets and allowed erasure policy are unknown here. Never claim destroy removed every backed-up version. [Cloudinary Upload destroy semantics](https://cloudinary.com/documentation/image_upload_api_reference#destroy_method), [Admin backup APIs](https://cloudinary.com/documentation/admin_api).
